# Stage 7 — Livestock & equipment caveats

**Load this when:** touching `libs/features/livestock-equipment/`, `libs/domain/stocking/`, livestock / equipment commands in `libs/domain/scene-model/`, or any F7.x feature.

## Architecture

- **Livestock + equipment are scene-resident, NOT SceneObjects.** `Scene.livestock?: LivestockEntry[]` and `Scene.equipment?: EquipmentEntry[]` are flat planning-inventory arrays — entries DO NOT belong to a `Layer`, are NOT painted on the canvas, and are NOT subject to the lock-guard policy. The `decorObjectId?: Uuid` slot on `LivestockEntry` is reserved for a future "decorative fish swimming" feature that would link an entry to a `DecorObject` in a layer; F7.1 ships without that link.
- **Livestock + equipment UIs are inventory, not placement.** `LivestockToolComponent` / `EquipmentToolComponent` have NO `HostListener` on document pointer events and NO drag service — clicking a catalog tile dispatches the matching `Add*Entry` command immediately. F7.1 / F7.3 deliberately don't compete with the canvas for pointer input.

## Livestock (F7.1) commands

- **Quantity floor is 1 in the UI, enforced in the command.** `UpdateLivestockQuantity` with `quantity < 1` or non-integer returns `{ ok: false, reason: 'invalid' }`. The − button at qty 1 must NOT dispatch (otherwise it would surface a `commandRejected` toast). Same model as the substrate-region extent inputs auto-correcting before dispatch.

## Stocking rules (F7.2)

- **Stocking rules are advisory and explainable.** Every rule in `libs/domain/stocking/` lives in its own `rules/<name>.ts` file with a co-located spec; the aggregator `evaluateStocking(scene, catalog)` runs all six and concatenates. **Rules don't short-circuit each other** — a temperature clash does NOT skip the temperament check. The UI is responsible for ordering / collapsing — the engine just emits everything that fires. Deterministic sort: severity desc (error → warning → info), then `code` alphabetical, then comma-joined sorted `relatedEntryIds`. Stable across re-evaluations, which the UI relies on for `track w.id` keys.
- **Bioload heuristic math.** `weighted_body_cm = Σ (adultSize_mm / 10) × quantity × class_mult` where `class_mult` is `0.5` / `1.0` / `2.0` for `bioloadClass` low / medium / high. Divide by tank litres `(tank.width × tank.depth × tank.height) / 1_000_000`. Tiers: `< 1.0` → no warning, `1.0–1.5` → info `bioload-near-capacity`, `1.5–2.5` → warning `bioload-overstocked`, `≥ 2.5` → error `bioload-severely-overstocked`. The thresholds + class multipliers are exported `const` values in `rules/shared.ts` so the F7.4 setup sheet can reuse the same math + future tuning is one place. The heuristic is COARSE BY DESIGN — the plan calls it "rough bioload vs. tank volume." Don't pretend it's a calibrated formula.
- **Range-intersection rules (temperature, pH) treat touching ranges as compatible.** `max(minC)` exactly equals `min(maxC)` → no warning (species can coexist at a single point). Strict inequality required to fire. The "touching" boundary case is documented in the rule's JSDoc + has a regression test.
- **Fin-nipper detection uses a hardcoded long-finned id allow-list.** `LONG_FINNED_CATALOG_IDS = new Set(['livestock.fish.betta-splendens'])` lives in `rules/fin-nippers.ts`. Adding a future angelfish / fancy guppy means adding to this set, NOT re-evaluating the schema. Cheap to extend; deliberately not catalog metadata since "what counts as long-finned" is a judgment call the rule owns.
- **Stocking selector + mock-store testing.** `selectStockingWarnings` chains off `selectScene`, which means TEST suites using `provideMockStore` MUST override `selectStockingWarnings` directly with a known value — without an override the underlying scene is `undefined` and the rule engine throws. The leak-across-`resetTestingModule` gotcha applies here too: every configure() must re-set both `selectLivestock` AND `selectStockingWarnings`. See `livestock-tool.component.spec.ts` for the canonical pattern.
- **Stocking-guidance UI hides when empty.** `LivestockToolComponent` does NOT render a "All clear!" placeholder when `warnings()` is empty — the whole "Stocking guidance" section + subheading is omitted via `@if`. Keeps the panel compact. The header badge counts inventory entries, NOT warnings, so a clean tank looks the same as a tank with no livestock yet.

## Equipment (F7.3) commands + UI

- **`SetEquipmentNote` empty-string contract.** Note is `string | null`. **`null` removes the property entirely** (round-trip "absent stays absent" — JSON.stringify drops `undefined` but not `null`, and the schema's `additionalProperties: false` rejects literal `null`). **`''` is REJECTED with `'invalid'`** so the UI MUST either dispatch a real note or `null` to clear. `EquipmentToolComponent`'s note input encodes this: trim the draft on blur, dispatch `null` when length is 0 else the trimmed string. Same null-vs-property-absent pattern as `SetObjectGroupId`.
- **`UpdateEquipmentSettings` wholesale-replaces.** No merge — matches `SetTankStyle` / `SetSubstrateRegionProfile`. Every value in the new settings must be a primitive `number | string | boolean`; nested objects / arrays / `null` values reject with `'invalid'`. `settings: null` deletes the property entirely. The catalog's `defaultSettings` are shallow-cloned into the new entry on `AddEquipmentEntry` so downstream edits don't mutate the catalog source. **F7.3 does NOT ship a settings editor UI** — the command exists for future iteration; the current UI displays settings as a read-only `<dl>` and the Add path's defaults are the only writer.
- **Equipment-tool note input has a save-on-blur no-op guard.** Per-row local edit state (`Map<entryId, string>` signal) lets users type without dispatching per-keystroke; blur compares trimmed draft to current `entry.note ?? ''` and dispatches ONLY when they differ. Blur with no prior edit (`draft === undefined`) is a no-op. Blur with the same value clears the draft so future edits read fresh from the entry. This keeps the action stream free of `commandRejected` and per-keystroke spam.
- **F7.3 UI uses `[value] + (input) + (blur)` — no FormsModule.** Keeps the lib's public surface unchanged; FormsModule is an implementation detail of the note input. If a future component needs `[(ngModel)]`, scope FormsModule to that component only — don't promote it.

## Setup sheet (F7.4)

- **`summarizeScene` runs `evaluateStocking` inline.** F7.4 lives in `libs/features/export/src/lib/summary.ts`. The setup sheet is the same output the F6.2 Export dialog produced — extended with livestock + equipment + stocking-warnings sections. The aggregator calls `evaluateStocking(scene, catalog)` directly (no NgRx selector) because the export lib is a pure Node-Jest lib with no Angular/state dependency. **When `catalog === null`** (legacy callers without a catalog) the warnings section is empty — the rules engine can't resolve livestock refs without a catalog and surfacing an exception in the Markdown output would be hostile.
- **F7.4 Markdown sections omit themselves when empty.** No "_None._" placeholder for livestock / equipment / stocking — sections only appear when they have content. The empty placeholder is reserved for plants / hardscape (existing F6.2 convention) because a fishless tank is normal but a plantless aquascape isn't the intent.
- **F7.4 wattage total is "published wattage only".** Items without a published `wattage` contribute 0 to the sum. The Markdown formatter ALSO omits the "Total wattage" line when the sum is 0 — so a tank with only sponge filters + un-spec'd lights doesn't render a misleading "Total wattage: 0 W" footer.
- **F7.4 coverage rendering is asymmetric.** `coverageLitres` may have both, just-min, or just-max — render as `N–M L`, `N L+`, or `up to M L` respectively. Falls through silently when both are null (e.g. catalog entry has the `coverageLitres` key but no values — unlikely but defensive).
- **F7.4 stocking warnings include `relatedEntryNames`** alongside the raw `relatedEntryIds`. The export lib looks up each id in the scene's livestock + resolves the catalog name, so the Markdown reads "Affects: Neon Tetra (Paracheirodon innesi)" instead of an opaque uuid. Names ordering matches the raw id ordering for stable output.
- **`features-export` has an explicit 80% branch coverage gate** in its jest.config.ts and is wired into the CI coverage selector. F7.4 added enough per-section defensive guards (catalog-entry-missing, coverage-min-only, coverage-max-only, etc.) that the lib follows the same pattern other feature libs use.
