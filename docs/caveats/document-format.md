# Document format caveats

**Load this when:** touching `libs/domain/document/` (the `.aqua` schema, migrations, validator, marshal) or any code that round-trips a document to disk.

- **Current schema is v5.** Every future change needs: (a) appended `{ from: N, to: N+1, migrate }` in `AQUA_MIGRATIONS` (`libs/domain/document/src/migrations.ts` — the chain reads top-down v1 → v2 → v3 → v4 → v5 → …; `runMigrations` sorts by `from` so order is cosmetic, but keep it readable), (b) `CURRENT_SCHEMA_VERSION` bumped, (c) previous example preserved as round-trip fixture (see `libs/domain/document/src/__fixtures__/example.v1.aqua.json` + `example.v2.aqua.json` + `example.v3.aqua.json` + `example.v4.aqua.json` for the canonical historical pins, each with a `vN-fixture-migration.spec.ts`), (d) fast-check property test in `libs/testing` covering the new step, (e) `pnpm precompile:validators` re-run (CI diffs the generated `.cjs` — revert the unrelated catalog validator's non-deterministic `.cache/aquascape-validators/<hash>` scratch-path comment line so its diff stays clean). **Bumping the version also re-points the prior fixture specs at the full chain to current** — when you bump to vN, the v1…v(N-1) fixture specs must now assert `schemaVersion === N`, the full applied-step list, and absence of every later-added field (each additive step is a version-stamp identity), and the `serialize.spec.ts` "runs migrations before validation" test must hypothesize an `(N) → (N+1)` step. `nx test testing -t document-round-trip` is REQUIRED on main.
- **Migrations are usually additive identities, but they don't have to be.** v1→v4 were pure version-stamp pass-throughs (additive optional fields). **v5 is the first removal**: it deletes a key (`renderHistory`). A removal migration is still pure + total — build a fresh object via rest-destructuring (`const { droppedKey: _, ...rest } = doc; return { ...rest, schemaVersion: N }`), never mutate the input, never throw. The new schema's `additionalProperties: false` then rejects any doc that *still* carries the removed key, which is exactly why the migration must strip it before validation runs.
- **v2 added `Layer.zone?: 'foreground' | 'midground' | 'background'`.** Optional + additive — the migration `{ from: 1, to: 2 }` is an identity that only bumps `schemaVersion`. v1 docs (no `zone` on any layer) load + validate cleanly under the v2 schema. Consumed by `renderer-3d` to band-remap object Z; never required by the 2D renderer.
- **v3 added `Tank.waterLevelMm?: Millimetres`** — the water-surface height above the interior floor, canonical integer mm, authored via scene-model's `SetWaterLevelCommand`. Optional + additive — the migration `{ from: 2, to: 3 }` is the same version-stamp pass-through shape as v1 → v2 and MUST NOT invent a value. **Absent stays absent**: "no field" means "default fill", derived at render/consume time by scene-model's `effectiveWaterLevelMm()` (= `height − DEFAULT_WATER_GAP_BELOW_RIM_MM`); neither the migration nor the marshal (`documentToScene`/`sceneToDocument` carry `tank` verbatim) may materialise that default into the document. The `[1, height]` range is advisory — the upper bound is a cross-field comparison JSON Schema can't express, so the schema only enforces `integer ≥ 1` and consumers clamp via `effectiveWaterLevelMm`.
- **v4 added `Tank.waterChemistry?: WaterChemistry`** (Stage 13 F13.2 / ADR-0006) — a persisted snapshot of the `domain/water-sim` simulation so a saved tank reloads mid-cycle. Shape: `{ chemistry: {...}, cycle, algae? }`. The `chemistry` block is a **field-for-field mirror of `water-sim`'s `WaterState`** (`ammonia`/`nitrite`/`nitrate`/`ph` + the `aobColony`/`nobColony` capacities + the `ageWeeks` cycling clock + `engineVersion`) — **every field is a persisted snapshot, none is recomputed**: the model cannot reconstruct the colony capacities, the clock, or the engine provenance from concentrations alone, so the full state is the resume point. `cycle` (`'uncycled' | 'cycling' | 'cycled'`) is **denormalized** — it's a pure function of `chemistry` (`water-sim`'s `cycleProgress`) but persisted so offline readers display the stage without importing the model; consumers that DO import `water-sim` may recompute it. `algae` is an optional per-type coverage block (`green-spot`/`hair`/`black-beard`/`diatom`), each scalar omitted when zero — genuinely independent accumulated state. Optional + additive — the migration `{ from: 3, to: 4 }` is the same version-stamp pass-through as v2 → v3 and MUST NOT invent chemistry. **Absent stays absent**: "no field" means "no chemistry recorded" (the tank was never cycled in the editor); inventing a snapshot would falsely claim a tank had been cycled. The marshal carries `tank` verbatim, so the field round-trips with no marshal edit. The live tick is owned by a runtime `WaterChemistryService` (not the document).
- **v5 REMOVED `renderHistory` (and the `RenderRecord` interface).** The AI photorealistic render feature (Stage 9) was dropped from scope, so the optional `AquaDocument.renderHistory?: RenderRecord[]` field — always optional, never written by any shipped code — was retired. The migration `{ from: 4, to: 5 }` is the **first non-identity step**: it STRIPS `renderHistory` if present (rest-destructure, pure + total) so a doc that somehow carried it loads cleanly under the v5 schema (whose `additionalProperties: false` no longer admits the field). On every real document the strip is a no-op (no writer ever emitted it). The marshal lost its `renderHistory` envelope passthrough (the `DocumentEnvelope` is now strictly `{ meta, extensions? }`); `AssetRef` is **kept** (it's still used by `TankStyle.background.image`). `nx test testing -t document-round-trip` covers the strip case.
- `aqua-document.ts` + `aqua-document.schema.json` + `example.aqua.json` + in-memory mirror in `libs/domain/scene-model/src/types.ts` must be updated **together**. `node tools/validate-example.mjs` is the one-line contributor sanity check.
- **`arbFiniteNumber` folds `-0` → `0`** because `JSON.stringify(-0) === "0"` but `Object.is(-0, 0) === false` and Jest's `toEqual` distinguishes them. A raw `fc.double` producing `-0` breaks the format invariant.
- **Loader preflight order:** container unwrap → JSON.parse → if `schemaVersion` missing/non-number, run validator FIRST (so the user sees `schema-invalid` not a confusing `missing-migration` 0 → 1) → `runMigrations` → `validateAquaDocument`.
- **Marshaling preserves unknown extensions; livestock + equipment live on the Scene.** `documentToScene` / `sceneToDocument` carry the envelope (`meta` + optional `extensions`) verbatim — don't drop what you don't understand. **Livestock (Stage 7 F7.1) and equipment (Stage 7 F7.3) are the user-editable fields:** they live on `Scene.livestock` / `Scene.equipment` (NOT on `DocumentEnvelope`) so the Command pipeline can mutate them for undo/redo. The marshal moves them from `doc.{livestock,equipment}` to `scene.{livestock,equipment}` on load and back on save. **DO NOT also expose either on `DocumentEnvelope`** — there's only one writer per field, and that's the Scene. `extensions` is the forward-compatibility escape hatch for things the editor doesn't model. (The `renderHistory` envelope field was retired in schema v5 when the AI render feature was dropped from scope — the `DocumentEnvelope` is now strictly `{ meta, extensions? }`.)
