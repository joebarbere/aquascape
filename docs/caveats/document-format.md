# Document format caveats

**Load this when:** touching `libs/domain/document/` (the `.aqua` schema, migrations, validator, marshal) or any code that round-trips a document to disk.

- **Current schema is v3.** Every future change needs: (a) appended `{ from: N, to: N+1, migrate }` in `AQUA_MIGRATIONS` (`libs/domain/document/src/migrations.ts` — the chain reads top-down v1 → v2 → v3 → …; `runMigrations` sorts by `from` so order is cosmetic, but keep it readable), (b) `CURRENT_SCHEMA_VERSION` bumped, (c) previous example preserved as round-trip fixture (see `libs/domain/document/src/__fixtures__/example.v1.aqua.json` + `example.v2.aqua.json` for the canonical historical pins, each with a `vN-fixture-migration.spec.ts`), (d) fast-check property test in `libs/testing` covering the new step, (e) `pnpm precompile:validators` re-run (CI diffs the generated `.cjs`). `nx test testing -t document-round-trip` is REQUIRED on main.
- **v2 added `Layer.zone?: 'foreground' | 'midground' | 'background'`.** Optional + additive — the migration `{ from: 1, to: 2 }` is an identity that only bumps `schemaVersion`. v1 docs (no `zone` on any layer) load + validate cleanly under the v2 schema. Consumed by `renderer-3d` to band-remap object Z; never required by the 2D renderer.
- **v3 added `Tank.waterLevelMm?: Millimetres`** — the water-surface height above the interior floor, canonical integer mm, authored via scene-model's `SetWaterLevelCommand`. Optional + additive — the migration `{ from: 2, to: 3 }` is the same version-stamp pass-through shape as v1 → v2 and MUST NOT invent a value. **Absent stays absent**: "no field" means "default fill", derived at render/consume time by scene-model's `effectiveWaterLevelMm()` (= `height − DEFAULT_WATER_GAP_BELOW_RIM_MM`); neither the migration nor the marshal (`documentToScene`/`sceneToDocument` carry `tank` verbatim) may materialise that default into the document. The `[1, height]` range is advisory — the upper bound is a cross-field comparison JSON Schema can't express, so the schema only enforces `integer ≥ 1` and consumers clamp via `effectiveWaterLevelMm`.
- `aqua-document.ts` + `aqua-document.schema.json` + `example.aqua.json` + in-memory mirror in `libs/domain/scene-model/src/types.ts` must be updated **together**. `node tools/validate-example.mjs` is the one-line contributor sanity check.
- **`arbFiniteNumber` folds `-0` → `0`** because `JSON.stringify(-0) === "0"` but `Object.is(-0, 0) === false` and Jest's `toEqual` distinguishes them. A raw `fc.double` producing `-0` breaks the format invariant.
- **Loader preflight order:** container unwrap → JSON.parse → if `schemaVersion` missing/non-number, run validator FIRST (so the user sees `schema-invalid` not a confusing `missing-migration` 0 → 1) → `runMigrations` → `validateAquaDocument`.
- **Marshaling preserves unknown extensions; livestock + equipment live on the Scene.** `documentToScene` / `sceneToDocument` carry the envelope (`meta` + optional `renderHistory` / `extensions`) verbatim — don't drop what you don't understand. **Livestock (Stage 7 F7.1) and equipment (Stage 7 F7.3) are the user-editable fields:** they live on `Scene.livestock` / `Scene.equipment` (NOT on `DocumentEnvelope`) so the Command pipeline can mutate them for undo/redo. The marshal moves them from `doc.{livestock,equipment}` to `scene.{livestock,equipment}` on load and back on save. **DO NOT also expose either on `DocumentEnvelope`** — there's only one writer per field, and that's the Scene. `renderHistory` is reserved for Stage 9 (AI render history is non-user-editable — the renderer effect appends to it); `extensions` is the forward-compatibility escape hatch for things the editor doesn't model.
