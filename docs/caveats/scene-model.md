# Scene model + commands caveats

**Load this when:** authoring or editing `Command` types in `libs/domain/scene-model/`, touching undo/redo, or wiring a new editor mutation.

- **Commands are plain discriminated-union records** (not classes), dispatched through free `applyCommand` / `invertCommand`. Chosen for trivial JSON round-trips + inspectability.
- **Lock-guard policy:** locked layers reject *object-level* commands via `CommandResult` (`{ ok: false, reason: 'locked' | 'not-found' | 'invalid', message }`). Layer-metadata commands (rename / opacity / visibility / locked) and global ops (`SetTankDimensions` / `SetTankStyle`) are NOT blocked.
- `MoveObject` carries absolute world position. `ReorderLayers` takes a full id-permutation.
- `SetTankDimensions` validates against 100–10 000 mm, clamps every object's `transform.position` into the new interior AABB. **Nothing is deleted**, even when an object's centre lands on a face. Invert carries `inverse: { previousDimensions, restoredPositions }`; apply **short-circuits the clamp when `restoredPositions` is present** (this is how shrink-and-undo restores originals).
- `SetTankStyle` is whole-style replacement, `structuredClone`-cloned on store, always-on validation (hex regex + sorted-stops + finite angle + image `AssetRef` shape). Substrate `SetSubstrateRegionProfile` follows the same wholesale-replace pattern.
- `MirrorObject` is **self-inverse** (no captured state; apply twice = identity). `Duplicate` isn't a new command — the inspector composes `AddObject` of a `JSON.parse(JSON.stringify())`-cloned object with a fresh id + 20 mm offset.
- **`MirrorObject` rejects `axis: 'y'` on plant objects** with `reason: 'invalid'`. Plants must always grow upward from the substrate; a vertically-mirrored plant would have its roots in the air. The selection inspector's Mirror V button is disabled when any selected object is a plant (so the user sees the constraint surfaced in the UI), and the 2D + 3D renderers ignore `plant.transform.flipY` entirely (sy stays positive) as defence in depth for any legacy document that smuggled `flipY: true` past the command guard.
- `SetObjectGroupId({ objectIds, groupId: null })` REMOVES the property entirely. The schema's `additionalProperties: false` won't accept literal `null`; "ungrouped" must round-trip as "no field present". When `inverse.previousGroupIds` is present, per-object restoration takes precedence over the uniform `groupId`.
- **History is bounded immutable** (default 200). `setScene({ scene })` replaces wholesale and resets history — deliberately NOT a Command (you don't undo opening a file). Used by Open / New / Recover.
- **`setTankPresetRef`** is a metadata-only side-edit that bypasses the Command pipeline.
- **`DoseNutrient` is RUNTIME-ONLY (chemistry deferred to Stage 13).** The command does NOT touch water chemistry — `Tank.waterChemistry` is a future Stage 13 field that does not exist yet. Instead it appends a `DoseEvent` to the new optional `Scene.doseLog?: readonly DoseEvent[]`; `invert` is `RemoveDoseEvent` (re-inserts at the captured index). A future water-sim consumes `doseLog` to apply deltas. **`doseLog` is NOT persisted** — `example.aqua.json` + the document marshalling are untouched, so `document-round-trip` stays green; the optional-absent field round-trips losslessly. Persistence is a separate, deferred PR (owned by `aqua-document-guardian`).
- **`DoseEvent` deltas are computed in the `doseNutrient(nutrient, amount, { id, seq, unit? })` factory, NOT in apply/invert.** The factory takes the already-resolved catalog `NutrientEntry` (structurally `ResolvedNutrient` — scene-model keeps zero dep on `domain/catalog`) and bakes a finished event so apply/invert stay a pure push/pop with no catalog access. **Disclosed** product → `deltas[axis] = contributes[axis] × (amount / dose.amount)` (linear scale, e.g. KNO3 `+4.84 ppm NO3 / 0.3 g` dosed at `0.6 g` → `{ no3: 9.68 }`). **Proprietary** (`disclosed: false`) → `deltas` OMITTED entirely; only the qualitative `affects` list is recorded. Never fabricate ppm. `seq` is a monotonic ordering key — pass `nextDoseSeq(scene)`.
- **No locked-layer guard on dosing.** A `DoseEvent` belongs to no layer, so the object-level lock policy doesn't apply (same reasoning as livestock/equipment commands) — dosing runs regardless of any layer's `locked` flag. Selectors: `selectDoseLog` / `selectDoseEventById` / `nextDoseSeq`.
- **`WaterChange` (Stage 13 F13.5a) dilutes the water column, NEVER the bacterial colony.** The single load-bearing biology invariant: nitrifying bacteria (`aobColony` / `nobColony`) live on SURFACES — filter media, substrate, hardscape — not suspended in water. So `apply` blends only the *dissolved* compounds (`new = current·(1−f) + replacement·f` for `ammonia`/`nitrite`/`nitrate`, and `ph` toward `replacement.ph` when given) and leaves `aobColony` / `nobColony` / `ageWeeks` / `engineVersion` untouched. A water change therefore can NEVER reset cycling — a cycled tank stays cycled. The denormalized `cycle` stage is recomputed from the new chemistry; the `algae` block is carried through unchanged (a water change doesn't scrub surfaces). Getting this wrong would let the sim "re-cycle" on every change. Built via `waterChange(fractionReplaced, replacement?)`; `fractionReplaced ∈ (0, 1]`, `replacement?` defaults to clean source water (0 ammonia/nitrite/nitrate; pH unchanged).
- **`applyWaterChange(chemistry, fractionReplaced, replacement?)` is the single source of dilution truth.** The pure, framework-free helper the command uses AND the runtime `WaterChemistryService` (F13.5b) imports to dilute its live `WaterState` — so model + live tick agree by construction. (`replacement.gh`/`.kh` are accepted by the helper for the runtime service, but the persisted `WaterChemistry.chemistry` block mirrors `WaterState` which has no gh/kh, so the command doesn't write them.)
- **`WaterChange` invert is capture-and-restore** (like `RemoveDoseEvent`): dilution is lossy, so `invert` captures the EXACT prior `Tank.waterChemistry` into `inverse.previousChemistry` and `apply` restores it verbatim when `inverse` is present. **No lock-guard** (not object-scoped). **Absent-`waterChemistry` edge case = clean reject** with `reason: 'invalid'` ("no recorded chemistry to dilute") — not a silent no-op; invert returns `Noop`.
- **The `cycle` classifier in `water-change-commands.ts` (`classifyCycle`) MIRRORS `water-sim`'s `cycleProgress`** (same `SAFE_NITROGEN_MG_L = 0.25` / `UNCYCLED_COLONY_FLOOR = 0.05` thresholds + branch order). It is re-declared rather than imported — same rationale as re-declaring `ResolvedNutrient` instead of depending on `domain/catalog`: keeping `scene-model`'s `nx build` graph dependency-light (importing `water-sim`, which transitively pulls catalog/livestock-behaviors, drags `water-sim`'s separate pre-existing `tsc rootDir` build break into scene-model's build chain). **Keep the two in lock-step**; the `water-change-commands.spec.ts` "mirrors water-sim cycleProgress" property test re-encodes the oracle to catch drift. The spec deliberately does NOT `import` water-sim either, for the same build-graph reason.
