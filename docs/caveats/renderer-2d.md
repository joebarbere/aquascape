# renderer-2d caveats

**Load this when:** touching `libs/rendering/renderer-2d/` — paint order, hit-test, selection handles, or any view-only overlay that needs a render-pass slot.

- **Canvas sizing is asymmetric: backing buffer only.** `syncCanvasSize` writes `canvas.width` and `canvas.height` (integer DPR-scaled pixels for the backing store) but DOES NOT write `canvas.style.width` / `.style.height`. The host stylesheet (`apps/web/src/app/app.component.ts`'s `.scene-canvas { width: 100%; height: 100%; }`) owns the CSS box; the renderer only owns the bitmap. Writing inline CSS pins the canvas at whatever interim dimensions it had on first `attach`, before async-hydrated sidebar/rail widths and the recovery banner have settled — the ResizeObserver then reads back the renderer's own frozen value and the tank stays painted at the top of an oversized canvas-host (visible as "tank pushed up" in screenshots). Regression test is `does NOT write inline canvas.style.width / .height` in the renderer spec.
- **Paint order:** **backdrop photo (F6.3 — view-only, painted FIRST in CSS-pixel space under identity transform so it covers the whole canvas and doesn't zoom with the scene)** → **wall background (Stage 5.x — view-only, world-space rect behind the tank)** → background (tank `style.background`, painted INSIDE the tank rect only) → grid → tank outline → substrate (Catmull-Rom silhouette + deterministic grain noise, `seed XOR fnv32(region.id)`) → water tint (inside tank, `globalAlpha = 0.25`) → frame overlay (8 mm rim for `'framed'`, +10 mm centre brace for `'braced'`) → hardscape **+ decor** silhouettes (one pass — see the decor bullet below) → plant silhouettes → **composition overlays (F5.3, golden ratio / thirds / focal points — view-only)** → **snap alignment guides (F5.4 — magenta lines for engaged snap targets during drag)** → selection handles (drawn LAST).
- **F5.3 overlays are on `render` only, NOT on `hitTest`** — they are non-interactive decoration. When `overlayOptions` is omitted, or when every flag is false, the overlay pass is a true no-op (single early return, zero canvas state change). Each enabled overlay wraps its paint in its own `save`/`restore` so style state never leaks into selection-handle paint. Coords are tank-interior-relative (`(0, 0)` to `(tank.width, tank.height)` in world mm) — the world transform already in place from `render()` projects them the same way as scene content. Line widths and dash lengths are scaled by `1 / zoom` so they look identical at every zoom.
- **Decor = hardscape-convention silhouette.** `DecorObject`s paint, hit-test, and grow selection handles through the EXACT hardscape pipeline (`DecorEntry` shares the `naturalSize` / `color` / normalised-`[-1,1]`-silhouette fields): fill with `entry.color`, scale by `naturalSize × 0.5 × transform.scale`, flips as negative scale, rotation honoured, missing catalog entry → silently skipped in paint + AABB-fallback in hit-test — all identical to hardscape. Decor paints in the SAME layer walk as hardscape so within-layer back-to-front order is preserved across the two kinds. Only differences: the outline stroke is always the rock `#222` (the darker `#2a1a0e` stroke is hardscape-wood-only), and `DecorEntry.model` (the 3D GLB ref) is ignored entirely — 2D never fetches models.
- **Hit-test handle-beats-body:** when `selection` is supplied, handle hit-test runs FIRST. A click on a corner-handle square inside the silhouette returns `'scaleNE'`, not the body. Without `selection`, handles aren't painted and aren't hit-tested.
- **Selection handles for single-specimen plants only.** Scatter patches don't get bbox handles — "scale a brush" isn't the right gesture.
- **Plant silhouettes are base-anchored, not centre-anchored.** `paintSinglePlant` / `paintScatterPlant` translate to the world position, scale by `sx, sy` (always positive `sy` — see below), then `ctx.translate(0, 1)` so silhouette y=−1 (the root edge of every catalog `silhouette[]`) lands at the authored world Y. Growth scales `sy` upward and the base stays put — leaves extend up, roots stay anchored. Templates author `position.y` ≈ substrate-top so plants sit on the substrate. Without the post-scale `translate(0, 1)` the silhouette centre would land at position.y, dangling roots `sy` mm below the anchor.
- **Plant `transform.flipY` is ignored at the renderer.** `sy` is built without the flipY sign so a plant's vertical orientation is invariant under any legacy `flipY: true` field. The MirrorObject command also rejects axis='y' on plant kind (`commands.ts`) — this is defence in depth. flipX is honoured.
- **Grain noise skipped on regions < 20 mm wide** (sub-pixel speckle = flicker on resize).
- **Branch coverage lowered to 85 %** here (statement / line / function gates stay 90 %) — selection-handle paths + many small defensive guards aren't naturally exercised from unit tests.
- **Render() + hitTest() use options objects** (refactored from the 9-arg positional shape it had grown into through Stage 6). Signatures: `render(scene, viewport, options?: RenderOptions)` + `hitTest(point, scene, viewport, options?: HitTestOptions)`. `RenderOptions` carries `catalog` / `selection` / `previewAgeWeeks` / `overlayOptions` / `wallBackground` / `snapGuides` / `backdropImage`; `HitTestOptions` is a STRICT SUBSET (catalog / selection / previewAgeWeeks) because decoration-only fields aren't hit-testable. Every field is independently optional and "off / no-op when omitted" per the per-field docs. **`exactOptionalPropertyTypes`** rejects passing `undefined` to an optional field — call sites that compute a value-or-null must use the spread-trick `...(value !== null ? { key: value } : {})` rather than `key: value ?? undefined`. The arity is locked at 3 / 4 by `renderer-api/index.spec.ts` so a future drift back to positional args is a compile + runtime failure.
