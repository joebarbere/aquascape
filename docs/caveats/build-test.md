# Build / test prerequisites

**Load this when:** scaffolding a new lib, adding Jest coverage gates, touching CI workflow selectors, running `pnpm package:desktop`, regenerating icons, or debugging the app-name / userData path on desktop.

## Lib scaffolding

- **Every buildable lib needs a `package.json` with `"name": "@aquascape/..."`** matching its tsconfig path alias, or `@nx/js:tsc` cross-lib builds break with `TS6059: not under 'rootDir'` for transitive consumers.
- **Angular feature libs additionally need:** `jest-preset-angular` config + `tsconfig.json` with `experimentalDecorators: true` + `angularCompilerOptions` + `test-setup.ts` calling `setupZoneTestEnv()`. `layers-panel` and `planting-tool` test setups also polyfill `crypto.randomUUID` (jsdom 20 ships `crypto` without it; `newLayerId()` / `newObjectId()` call it).

## Coverage gates

- **Per-lib coverage gates** default to 90 % across statement / branch / function / line in `libs/domain/*`, `libs/rendering/renderer-2d`, `libs/platform/platform-{web,electron}`, `libs/state`, every implemented `libs/features/*`. **Branch exceptions** with a comment in each `jest.config.ts`: `rendering-renderer-2d` + `features-hardscape-tool` at 85 %; `features-editor-shell` + `features-layers-panel` + `features-planting-tool` + `features-livestock-equipment` at 80 %.
- **CSS budget warnings (not blocking).** Accordion CSS pushed `layers-panel` (2.13 kB), `substrate-tool` (2.69 kB), `planting-tool` (2.75 kB), and pre-existing `tank-setup` (3.79 kB) over the 2 kB `anyComponentStyle` warning. Production builds succeed; all under the 4 kB error budget.

## Icons + PWA

- **Icon pipeline lives in `tools/build-icons.mjs`.** Source of truth: `apps/web/src/favicon.svg`. Run `pnpm icons` to regenerate the full set: `apps/desktop/src/assets/icon.{png,ico,icns}` for Electron + `apps/web/src/icons/icon-{180,192,384,512}.png` for the PWA web manifest. Per-size rasterisation (`sharp` with density-boost) so glyph hinting stays sharp at every target size — not a blurry downscale from one master. ICNS: built via Apple's `iconutil` (macOS only; non-macOS warns + skips, trusting the committed binary). Production packaging (electron-builder) embeds the same ICNS in the `.app` bundle.
- **Icon-grid padding.** The `favicon.svg` viewBox is `-8 -8 80 80` (NOT `0 0 64 64`); the visible 64-unit tile occupies the centre 80 % of the canvas with ~10 % transparent padding on each side. Without this, dock-rasterised icons render ≈ 25 % larger than their neighbours because macOS doesn't apply its own inset. Internal coordinates (rect at 0,0→64,64, A at (10,54)→(32,8)→(54,54)) are unchanged; only the canvas grew.
- **PWA install (F6.4) lives in `apps/web/src/manifest.webmanifest` + `index.html`.** Manifest declares Aquascape as a standalone app (`display: standalone`, theme color `#0891b2` matching the brand mark, background `#0a1622` for the splash). `<link rel="manifest">` + `<link rel="apple-touch-icon">` + `theme-color` meta wire it into Chromium / Firefox / Safari install flows. `web/project.json` `assets` glob copies the manifest + every `icons/icon-*.png` into `dist/apps/web/browser/`.
- **Service worker (F6.4 offline)** is `@angular/service-worker` configured via `apps/web/ngsw-config.json`. Pre-caches the app shell (favicon, manifest, index, main.js, polyfills, styles) eagerly + lazy-caches assets / icons; runtime cache slot for `/catalog/**` with a 30-day TTL. Bootstrap registers via `provideServiceWorker('ngsw-worker.js', { enabled: !isDevMode(), registrationStrategy: 'registerWhenStable:30000' })` — dev disables the SW outright (no cache surprises while iterating), production registers 30 s after first stable so the SW doesn't compete with initial paint or first-input responsiveness. Build emits `ngsw-worker.js` + `ngsw.json` + `safety-worker.js` into `dist/apps/web/browser/`. Local testing requires `http://localhost` or HTTPS — `file://` won't register.

## Desktop packaging + dev bundle

- **Desktop installers (F6.4) live in `tools/package-desktop.sh` + `apps/desktop/electron-builder.json`.** `pnpm package:desktop [--dir|--mac|--win|--linux]` runs the full pipeline: build web + desktop main + preload via Nx → flatten the deeply-nested `dist/apps/desktop/{main,preload}/src/...` outputs into a clean `dist/apps/desktop/electron-app/` staging tree (predictable top-level `main/main.js` + `preload/preload.js` + `web/index.html` + `assets/`) → patch the resolver paths so the staged main.js finds its peers in the flatter layout → write a minimal package.json pinning the electron version → hand the tree to electron-builder. Output: `dist/apps/desktop/installers/`. macOS DMG (arm64 + x64), Windows NSIS (x64), Linux AppImage (x64) targets configured. **Code signing is OFF** (`identity: null`, `hardenedRuntime: false`) — real distribution needs an Apple Developer ID + Windows EV cert; the produced macOS .app installs but Gatekeeper requires a right-click → Open the first time (or `xattr -d com.apple.quarantine`). The staged-tree approach beats letting electron-builder traverse the Nx output because @nx/js:tsc emits `main/src/main/main.js` which electron-builder can't trace from a single project root; the resolver patch (`tools/package-desktop.sh` inline Node script) rewrites `path.join(..., '..', '..', '..', '..', 'web', ...)` → `path.join(..., '..', 'web', ...)` in the staged `main.js` so the runtime locates its files. **`--projectDir`** must be passed to electron-builder explicitly so the JSON's relative `directories.*` paths resolve from `apps/desktop/` (without it `pnpm exec` lands them at the workspace root). Smoke-tested by launching the packaged .app + verifying it stays alive for 4 s.
- **App name + version display.** `apps/desktop/src/main/main.ts` calls `app.setName('Aquascape')` *synchronously* before `app.whenReady()` so `app.getPath('userData')` resolves to `~/Library/Application Support/Aquascape/`. **After** the storage-path is cached (`const storagePath = path.join(app.getPath('userData'), 'aquascape-storage.json')` handed to `createStorageBackend` as a constant thunk), the name is re-set to `Aquascape (${version})` — `(dev)` for unpackaged runs, `(app.getVersion())` for packaged builds (matching parens around both). The cache step is load-bearing: `app.getPath('userData')` resolves lazily from the current `app.getName()` each call, so re-naming for the dock display would otherwise move the storage file between writes. **On macOS, JS `app.setName()` does NOT update the dock-hover tooltip / menu-bar app name** — those come from `CFBundleName` in the launched `.app` bundle's `Info.plist`, which macOS reads before our JS runs. To make the dock hover show "Aquascape (dev)" instead of "Electron", `tools/build-dev-bundle.sh` (run via `pnpm dev-bundle`, automatically by `pnpm restart:desktop`) clones `node_modules/electron/dist/Electron.app` into `apps/desktop/.dev-bundle/Aquascape (dev).app`, patches `CFBundleName` + `CFBundleDisplayName` via `PlistBuddy`, and swaps `Contents/Resources/electron.icns` for our ICNS. The restart script then launches the cloned bundle's binary directly (`open --args` would detach the process; we want it foreground for Ctrl-C teardown). Per-clone, gitignored (`apps/desktop/.dev-bundle/`); APFS copy-on-write makes the bulk clone near-instant. Linux + Windows fall back to plain `electron`. Production packaging sets `CFBundleName` via the packager and the dev bundle becomes unnecessary.
- **userData path migration (one-time).** Pre-name-fix dev runs wrote autosave drafts + recent-files to `~/Library/Application Support/Electron/aquascape-storage.json`. After the fix the storage moves to `~/Library/Application Support/Aquascape/aquascape-storage.json` — existing dev data is stranded at the old path. Acceptable one-time loss for the dev-only environment; if a user reports missing recent files after pulling the change, the fix is to move `aquascape-storage.json` from the `Electron/` to the `Aquascape/` directory.
