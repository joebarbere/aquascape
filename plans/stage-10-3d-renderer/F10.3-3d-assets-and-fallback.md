# F10.3 — 3D assets + billboard fallback

**Stage:** 10 — 3D Renderer
**Owner:** `catalog-engineer`
**Collaborators:** `renderer-engineer`, `test-engineer`
**Status:** Not started

## Goal

Author and load 3D meshes for hardscape and selected plants, with a graceful billboard fallback where no mesh exists.

## Spec reference

Plan Stage 10 F10.3.

## Dependencies

**Requires:** F10.1.
**Enables:** Visually convincing 3D scenes.

## Scope

**In:**

- Catalog schema additions (optional fields):
  - `meshRef?: { path: string; format: 'glb' | 'gltf' }` on `HardscapeCatalogEntry` and `PlantCatalogEntry`.
  - Mesh assets live alongside thumbnails in the catalog ZIP.
- Mesh loading via `GLTFLoader` (Three.js).
- Fallback for entries without a mesh: render a billboard (a flat textured plane) that always faces the camera, using the existing thumbnail / outline data.
- Performance: stream meshes lazily — only load meshes for visible objects.

**Out:**

- Authoring tools for meshes — meshes are pre-authored outside the app.
- Animated meshes — out for v1.

## Acceptance criteria

- [ ] Hardscape entries with `meshRef` render as meshes; those without render as billboards.
- [ ] Plant entries without meshes render as billboards.
- [ ] Lazy loading: opening a doc with 100 objects loads meshes only for visible ones (verified by network/asset-fetch counter).
- [ ] Mesh load errors fall back to billboards cleanly with a logged warning.

## Testing

- **Unit:** mesh ref handling; lazy-load gating.
- **Integration:** load a fixture catalog with mixed mesh/no-mesh entries; verify both render paths.
- **Snapshot:** known mesh-rendered scene matches reference framebuffer.

## Notes

- **Asset size.** Meshes are heavy; cap individual mesh size (e.g. <500 KB compressed) and document. Big meshes belong in expansion catalogs, not core.
- **Licensing.** All meshes must be original or CC0. Don't ship anything you can't redistribute.
