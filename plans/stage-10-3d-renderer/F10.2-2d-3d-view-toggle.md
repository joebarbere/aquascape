# F10.2 — 2D / 3D view toggle

**Stage:** 10 — 3D Renderer
**Owner:** `angular-feature-engineer`
**Collaborators:** `renderer-engineer`, `test-engineer`
**Status:** Not started

## Goal

Toggle between 2D and 3D views of the same document. Orbit / pan / zoom camera in 3D. Selection and edits preserved across the toggle.

## Spec reference

Plan Stage 10 F10.2.

## Dependencies

**Requires:** F10.1.
**Enables:** Stage 10 milestone.

## Scope

**In:**

- View-toggle button in the editor shell (`features/editor-shell/`).
- On toggle:
  - Dispose the current renderer.
  - Instantiate the other renderer.
  - Attach to the canvas; render the current scene.
  - Preserve selection.
- 3D camera controls (Three.js OrbitControls or a small custom controller): mouse drag = orbit, middle-drag = pan, wheel = zoom; touch equivalents.
- Default 3D camera position computed from the scene's tank dimensions (fit-to-view).
- 2D viewport preserved across toggle (so toggling 2D → 3D → 2D returns to the same 2D framing).

**Out:**

- Editing 3D-only properties — assume all edits work in both views (per the architecture's promise).
- Animated transition between views — defer; instant snap is fine.

## Acceptance criteria

- [ ] Toggle preserves selection and document state.
- [ ] 3D camera controls work on mouse + touch.
- [ ] 2D viewport is restored exactly when toggling back from 3D.
- [ ] Toggle does not mark the document dirty.

## Testing

- **Component:** toggle state preserved across renderer switch.
- **E2E:** toggle to 3D, orbit, place an object, toggle back — document unchanged.

## Notes

- **Tool compatibility.** Some tools (e.g. substrate profile editing) are inherently 2D; in 3D view, either hide them or open a 2D overlay for the edit. Don't try to make every tool work natively in 3D for v1.
- **Camera state is view state.** It lives in NgRx, not in the document.
