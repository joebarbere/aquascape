# F9.2 — Dual provider support (local + hosted)

**Stage:** 9 — AI Photorealistic Render
**Owner:** `electron-platform-engineer` (key storage), `angular-feature-engineer` (provider selector)
**Collaborators:** `test-engineer`
**Status:** Not started

## Goal

One `RenderProvider` interface, two concrete implementations: a local on-device / self-hosted model and a hosted bring-your-own-key API. User picks; document records which kind produced each result.

## Spec reference

Plan Stage 9 F9.2.

## Dependencies

**Requires:** F9.1 (RenderRequest shape).
**Enables:** F9.3 (history records `kind`).

## Scope

**In:**

- Provider interface:
  ```ts
  interface RenderProvider {
    readonly id: string;
    readonly kind: 'local' | 'hosted';
    isConfigured(): Promise<boolean>;
    generate(req: RenderRequest, signal: AbortSignal): Promise<RenderResult>;
  }
  interface RenderResult {
    bytes: Uint8Array;
    width: number;
    height: number;
    request: RenderRequest;
    providerInfo: { id: string; kind: 'local' | 'hosted'; model?: string };
  }
  ```
- **Local provider:** points at a local HTTP endpoint (e.g. Automatic1111-style API, ComfyUI, or any image-gen API the user runs locally). Configurable URL. No data leaves the machine; verify in tests by mocking network as denied.
- **Hosted provider(s):** pluggable by name. Initial set includes at least one (e.g. Replicate, OpenAI image API, Stability — pick one and document; structure for multiple).
- **Key handling (per `electron-platform-engineer`'s posture):**
  - Hosted API keys stored in OS secure storage (`safeStorage` / Keychain / DPAPI / libsecret) via main process only.
  - **Keys never reach the renderer.** Renderer asks main to "render with provider X"; main fetches the key, makes the call, returns only the result image.
  - Keys never appear in serialized documents, logs, or error messages.
  - Web build cannot use hosted providers requiring server-side keys (or only with session-scoped keys not persisted in plaintext).
- Provider selector UI: lists configured providers; shows kind badge; lets user set the active provider; "configure…" entry leads to a settings panel for keys / URLs.

**Out:**

- Image-to-image / ControlNet specifics — keep request abstract; each provider implements its own conditioning if applicable.
- Fine-tuning UI — out of scope.

## Acceptance criteria

- [ ] Local provider works offline end-to-end against a stub local endpoint.
- [ ] Hosted provider works end-to-end against a mock HTTP server.
- [ ] Keys never appear in document serialization (verified by a sanitization test).
- [ ] Provider switching mid-session works cleanly.
- [ ] `isConfigured()` correctly reflects state for both providers.

## Testing

- **Unit:** key sanitization; provider selection logic.
- **Integration:** mock local server (offline-mode network guard); mock hosted server.
- **E2E:** with a stub local provider, render fully offline → result returned; with a stub hosted provider, configure key → render → key never appears in serialized doc.

## Notes

- **Capability detection.** Web build hides hosted providers that require server-side keys it can't securely hold (unless an explicit "session-only key" mode is wired). Document the rule.
- **AbortSignal.** Generations can be slow; let users cancel.
- **Image-to-image conditioning.** The flat render from F9.1 acts as the control image. Some providers (Replicate models with ControlNet, etc.) accept this directly; others may need a different wire format. Hide the difference behind the provider impl.
