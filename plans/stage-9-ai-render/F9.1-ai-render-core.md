# F9.1 — AI render core

**Stage:** 9 — AI Photorealistic Render
**Owner:** `angular-feature-engineer`
**Collaborators:** `renderer-engineer`, `aqua-document-guardian`, `test-engineer`
**Status:** Not started

## Goal

Generate a photorealistic preview of the finished design, conditioned on the scene description plus a flat 2D/3D render of the layout. The render panel, request builder, and result handling — provider-agnostic.

## Spec reference

Plan Stage 9 F9.1.

## Dependencies

**Requires:** F0.4 (renderer produces a flat reference image), F1.3 (renderHistory in schema, already present in v1), F9.2 (a provider must exist to call).
**Enables:** F9.3 (history attaches to the document).

## Scope

**In:**

- `RenderRequest` builder in a pure lib (`domain/ai-render` or in `domain/document`):
  ```ts
  interface RenderRequest {
    prompt: string;            // derived from scene metadata + user additions
    negativePrompt?: string;
    controlImage: Uint8Array;   // the flat 2D render of the layout
    seed: number;               // derives from document seed if user doesn't override
    width: number; height: number;
    style?: 'realistic' | 'illustrated' | ...;
  }
  ```
  Builder is pure — testable without a model.
- Prompt generation: derive a natural-language description from the scene (tank size, substrate, hardscape, key plants). Keep it short and template-based; users can edit.
- `features/ai-render/` panel:
  - Provider selector (from F9.2's configured providers).
  - Prompt textarea (pre-filled, editable).
  - Seed control (numeric input, "randomize" button).
  - "Generate" button → renders the flat reference, builds the request, dispatches to the active provider.
  - States: idle / loading / result / error / provider-not-configured.

**Out:**

- Provider implementations — F9.2.
- History — F9.3.

## Acceptance criteria

- [ ] `RenderRequest` builder is pure and tested against fixture scenes.
- [ ] Generated prompts are coherent and edit-friendly.
- [ ] Panel handles all five states cleanly.
- [ ] No provider-specific branches in the panel — switching providers does not change the UI shape.

## Testing

- **Unit:** prompt builder fixtures.
- **Component:** panel state machine.
- **E2E:** with a stub provider returning a fixed image, the panel produces a result that lands in history (covered jointly with F9.3).

## Notes

- **Don't let provider-specific options leak.** If a provider needs an extra parameter, add it to the abstract `RenderRequest` shape (optional) rather than branching the UI.
- **Editable prompts are essential.** The auto-generated prompt is a starting point; users will craft.
