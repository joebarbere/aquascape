# F9.3 — Render history

**Stage:** 9 — AI Photorealistic Render
**Owner:** `angular-feature-engineer`
**Collaborators:** `aqua-document-guardian`, `test-engineer`
**Status:** Not started

## Goal

Attach generated renders to the document via `renderHistory[]` so users can review, restore, or compare results — and so documents shared via the gallery (F8) come with their renders.

## Spec reference

Plan Stage 9 F9.3; `renderHistory[]` already present in `aqua-document.ts`.

## Dependencies

**Requires:** F9.1, F9.2, F1.3 (assets storage in `.aqua`).
**Enables:** Persistent, document-attached render gallery per project.

## Scope

**In:**

- Each successful render appends an entry to `scene.renderHistory[]`:
  ```ts
  interface RenderHistoryEntry {
    id: string; // UUID
    createdAt: IsoTimestamp;
    request: ResolvedRequest; // prompt, seed, control-image asset ref
    provider: { id: string; kind: 'local' | 'hosted'; model?: string };
    resultAssetRef: string; // path inside .aqua ZIP, e.g. "assets/renders/<uuid>.png"
  }
  ```
  (Exact shape per `aqua-document.ts` — coordinate with `aqua-document-guardian` if any tweak is needed.)
- Result asset is stored inside the `.aqua` ZIP container under `assets/renders/`.
- UI: history panel showing thumbnails, prompts, provider info, "Restore prompt" / "Delete" actions.
- Deletion removes both the history entry and the orphaned asset.

**Out:**

- Comparing two renders side-by-side — nice-to-have polish.
- Export individual renders as standalone files — covered by F6.1 patterns; users can right-click → save.

## Acceptance criteria

- [ ] Renders are attached to the document and round-trip via `.aqua`.
- [ ] `kind` field correctly reflects local vs. hosted.
- [ ] No keys / secrets in history entries.
- [ ] Deleting a render removes its asset too.
- [ ] Large render counts don't bloat the document beyond reasonable bounds (consider a soft cap / cleanup prompt past N entries).

## Testing

- **Unit:** asset cleanup on delete.
- **Integration:** round-trip a document with history through `.aqua`.
- **E2E:** generate → history entry appears → save → reopen → history present.

## Notes

- **Doc size discipline.** AI-render PNGs can be large. Consider downscaling to a reasonable display size when storing in the document, and keeping a separate "export-quality" copy outside the doc if needed.
- **Provenance for sharing.** When a doc with renders is published to the gallery, decide whether to strip history or keep it — surface as a publish-time toggle.
