# F2.3 — Substrate bands / regions with blending

**Stage:** 2 — Substrate Tool
**Owner:** `angular-feature-engineer`
**Collaborators:** `scene-model-engineer`, `renderer-engineer`, `test-engineer`
**Status:** Not started

## Goal

Let users place multiple substrate materials side-by-side along the tank width (e.g. aquasoil in the back, sand in the front) with optional blending at the boundary.

## Spec reference

Plan Stage 2 F2.3; substrate `regions[]` array with `fromX`, `toX`, `blend`, `profile` in `aqua-document.ts`.

## Dependencies

**Requires:** F2.1, F2.2.
**Enables:** more compositionally rich scapes — used heavily in Stages 4–5.

## Scope

**In:**

- Multiple `SubstrateRegion` entries per document (already in schema). Each region has `material`, `fromX`, `toX` (normalized 0–1), `blend` (0–1 transition width as fraction of region), `profile`.
- Region split/merge commands:
  - `SplitSubstrateRegion(atX, newMaterial)` — splits a region in two, replacing the right side's material.
  - `RemoveSubstrateRegion(id)` — extends the adjacent regions to fill the gap.
  - `SetRegionMaterial(id, materialRef)`.
  - `SetRegionBlend(id, blend)`.
- Renderer extension: render regions with their profiles; at boundaries, linearly cross-blend the two materials over the `blend` distance.
- UI: region list in the substrate panel; clicking a region selects it for editing; visual handles at region boundaries draggable to adjust `fromX` / `toX`.

**Out:**

- Vertical layering (e.g. cap-over-soil) — defer to a later stage or document as a possible extension.
- Per-region different profiles producing visible seams — the renderer must handle this; if it produces ugly artifacts, document the constraint and fall back to a shared profile across all regions.

## Acceptance criteria

- [ ] Multiple regions render correctly side-by-side.
- [ ] Blend transitions are visually smooth at the boundary.
- [ ] Region boundaries snap to 5% increments by default (with a modifier key to disable).
- [ ] Split / merge / boundary-drag are all undoable.
- [ ] An invalid layout (overlapping regions, `fromX >= toX`) is rejected by validation at command-apply time, not surfaced as a renderer bug.

## Testing

- **Unit:** region split/merge logic; boundary validation; cross-blend math.
- **Component:** drag a boundary updates `fromX`/`toX` correctly.
- **E2E:** create a 2-region substrate → adjust blend → save → reopen → identical.

## Notes

- **Bounded regions.** Enforce `0 ≤ fromX < toX ≤ 1` and "regions tile [0,1] without gaps or overlaps" as a class invariant on the `regions[]` array. Commands that would violate this are rejected.
- **Blend at edges.** No blending at `x=0` or `x=1` since there's no neighbor — clip the blend region to the next neighbor's bounds.
