# F2.1 — Substrate types

**Stage:** 2 — Substrate Tool
**Owner:** `catalog-engineer`
**Collaborators:** `renderer-engineer`, `angular-feature-engineer`, `test-engineer`
**Status:** Not started

## Goal

Define substrate as a catalog content type with realistic material entries (aquasoils, sands, gravels) and render each material with its characteristic texture / color in the 2D renderer.

## Spec reference

Plan Stage 2 F2.1; substrate region shape in `aqua-document.ts`.

## Dependencies

**Requires:** F0.4 (renderer), F1.3 (catalogRef in document).
**Enables:** F2.2 (shape needs a material), F2.3 (bands need materials), F6.2 (volume calc reads substrate displacement coefficient).

## Scope

**In, in `domain/catalog/`:**

- `SubstrateCatalogEntry` TypeScript type and a JSON Schema for it. Fields include:
  - `id`, `version`, display name, kind (`aquasoil` | `sand` | `gravel`).
  - Visual: base color, grain texture token (tileable texture id), grain size mm.
  - Spec: pH effect (buffering / neutral / acidic), nutrient (high / low / inert), recommended depth mm range.
  - `displacementCoefficient` (0–1) — used by F6.2 volume calc.
- A small starter `core` manifest with: ADA Amazonia, ADA Powder, generic black sand, generic white sand, common gravel.

**In, in `renderer-2d`:**

- Render a substrate region as a horizontally-filled band using a tileable texture pattern derived from the material's `texture token` + base color. Textures are pre-rendered to a canvas pattern at attach time and cached.

**In, in `features/substrate-tool/`:**

- Material picker UI (filter by kind, search by name).

**Out:**

- Substrate shape editing — F2.2.
- Multi-material bands / blending — F2.3.
- Catalog manifest loader — F2.4.

## Acceptance criteria

- [ ] At least 5 substrate entries shipped in the core catalog with accurate manufacturer specs (or clearly-marked generic entries).
- [ ] Substrate JSON Schema validates the shipped manifests and rejects malformed entries with a clear path.
- [ ] Renderer draws each material with a distinguishable appearance (manual visual check + a fixture-based snapshot test).
- [ ] Material picker is keyboard navigable and announces material specs.

## Testing

- **Unit:** schema validation accept/reject.
- **Component:** material picker filtering and selection emits the right command.
- **E2E:** pick a different material, observe renderer change, save, reopen — material preserved.

## Notes

- **Provenance.** Real-world substrate specs vary; cite sources in the manifest JSON or in a `provenance.md` for the core catalog so users (and maintainers) can verify. For generic entries, mark them as such.
- **Texture sourcing.** Shipped textures must be CC0 / public domain or self-generated. Avoid licensed material entirely.
