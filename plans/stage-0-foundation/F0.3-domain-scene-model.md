# F0.3 — domain/scene-model

**Stage:** 0 — Foundation & Walking Skeleton
**Owner:** `scene-model-engineer`
**Collaborators:** `renderer-engineer` (interface contract), `test-engineer`
**Status:** Not started

## Goal

Define the in-memory scene representation and the Command primitive that every editor mutation flows through. Build the undo/redo stack on top of Commands.

## Spec reference

Plan §2.3 (scene model), Stage 0 F0.3, `aqua-document.ts` (the on-disk shapes that the in-memory model must round-trip with).

## Dependencies

**Requires:** F0.1, F0.2.
**Enables:** F0.4 (renderer reads `Scene`), all later editor features (every feature dispatches Commands).

## Scope

**In, in `libs/domain/scene-model/`:**

- TypeScript types for the in-memory scene that match — or trivially map to — the on-disk shapes in `aqua-document.ts`:
  - `Scene` — root: tank, substrate, ordered `Layer[]`, metadata, seed.
  - `Layer` — id, name, opacity (0–1), visible, locked, ordered `SceneObject[]`.
  - `SceneObject` discriminated union: `HardscapeObject`, `PlantObject`, `SubstanceObject` — each carrying transform, catalogRef, per-type props.
  - Helper newtypes: `ObjectId`, `LayerId` (both UUID strings).
- **`Command` interface:**
  ```ts
  interface Command {
    readonly kind: string;
    apply(scene: Scene): Scene;
    invert(scene: Scene): Command;
  }
  ```
  Conforming commands are plain serializable data (no closures over runtime references).
- Concrete Commands sufficient for Stage 0 (more added per later features):
  - `NoopCommand` — used by tests and as a placeholder.
  - `AddLayer`, `RemoveLayer`, `RenameLayer`, `SetLayerOpacity`, `SetLayerVisibility`, `SetLayerLocked`, `ReorderLayers`.
  - `AddObject`, `RemoveObject`, `MoveObject`, `ReshapeObject` (general transform setter).
- `CompositeCommand` — bundles N child commands so they apply/invert as one user action (used later by brush/scatter).
- **Undo/redo stack:**
  ```ts
  interface History {
    push(c: Command, scene: Scene): { scene: Scene; history: History };
    undo(scene: Scene): { scene: Scene; history: History } | null;
    redo(scene: Scene): { scene: Scene; history: History } | null;
  }
  ```
  Pure, immutable; performing a new command after `undo` truncates the redo stack. Bounded length (e.g. 200), oldest entries drop deterministically.
- Pure selectors: `getObjectById(scene, id)`, `getLayerById(scene, id)`, `getActiveLayer(scene, activeLayerId)`, `iterateObjects(scene)` (visit order = render order).
- Locked-layer guard: commands targeting a locked layer return the unchanged scene and produce a typed `EditRejected` result (or throw a typed error — agent's call, document the choice).

**Out:**

- The pure 2D hit-test against scene objects can live here or in `geometry` — agent's call. If it lives here, it consumes `geometry` primitives.
- Persistence / serialization to `.aqua` — that's F1.3.
- NgRx integration — that's F1.6 / per-feature.

## Acceptance criteria

- [ ] Lib has tag `scope:domain`.
- [ ] Zero framework imports (Angular / DOM / Electron / NgRx / RxJS).
- [ ] `Scene` and friends are plain objects; `JSON.parse(JSON.stringify(scene))` deep-equals `scene`.
- [ ] Every concrete `Command` has property tests for `apply ∘ invert = id` and serializability.
- [ ] Undo/redo stack honors truncation on new-command-after-undo and the bounded length.
- [ ] Locked-layer guard is exercised by a unit test.
- [ ] Test coverage ≥90%.

## Testing

- **Unit:** every command's `apply` and `invert`. Selectors. History push/undo/redo edge cases (empty, single-command, at bound).
- **Property tests:**
  - For each command `c` and random scene `s`: `c.invert(c.apply(s)).apply(c.apply(s))` deep-equals `c.apply(s)`.
  - `JSON.parse(JSON.stringify(scene))` round-trip equality on randomly generated scenes.
  - History invariant: after any sequence of `push`/`undo`/`redo`, the current scene equals the result of replaying the live commands from the empty scene.
- **Component / E2E:** none (pure library).

## Notes

- **Type alignment with `aqua-document.ts`.** Where in-memory shapes diverge from on-disk shapes (e.g. derived caches), keep the divergence minimal and documented. The simpler approach is: in-memory `Scene` ≡ on-disk `AquaDocument` minus the `format`/`schemaVersion`/`meta` envelope. Recommend that approach unless a specific reason to diverge appears.
- **Mutation discipline.** Use spread/`structuredClone` for clarity in v1; optimize with structural sharing later if profiling demands it. Premature optimization here will hurt correctness.
- **Coordinate with renderer-engineer (F0.4).** The exact `Viewport` shape lives in `renderer-api`, not here; this lib should not import `rendering/*`. But the Scene shape must be sufficient for the renderer's needs — agree on it before locking the interface.
