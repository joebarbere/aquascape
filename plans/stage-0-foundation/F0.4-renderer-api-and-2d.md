# F0.4 — renderer-api + minimal renderer-2d

**Stage:** 0 — Foundation & Walking Skeleton
**Owner:** `renderer-engineer`
**Collaborators:** `scene-model-engineer` (interface contract), `test-engineer`
**Status:** Not started

## Goal

Define the renderer interface once, then ship the minimum 2D renderer that draws a tank rectangle and a grid against a canvas — proving the abstraction holds before any feature work piles on.

## Spec reference

Plan §2.4 (rendering abstraction), Stage 0 F0.4.

## Dependencies

**Requires:** F0.1, F0.2, F0.3.
**Enables:** F0.6 (app shells attach the renderer), F1.x and beyond (every visual feature draws via this).

## Scope

**In, in `libs/rendering/renderer-api/`:**

- Public types:

  ```ts
  interface RenderSurface {
    canvas: HTMLCanvasElement; // for renderer-2d; renderer-3d adds its own variant later
    devicePixelRatio: number;
    width: number; // CSS pixels
    height: number; // CSS pixels
  }

  interface Viewport {
    center: Vec2; // mm in the scene's projected 2D plane
    zoom: number; // pixels per mm
    rotation: number; // radians, 0 = upright; usually 0 in 2D
  }

  interface HitResult {
    objectId: ObjectId;
    layerId: LayerId;
    handle?: 'rotate' | 'scaleNW' | 'scaleNE' | 'scaleSW' | 'scaleSE' | 'translate';
  }

  interface SceneRenderer {
    attach(surface: RenderSurface): void;
    render(scene: Scene, viewport: Viewport): void;
    hitTest(point: Vec2, scene: Scene, viewport: Viewport): HitResult | null;
    dispose(): void;
  }
  ```

- No implementation in `renderer-api` — interfaces and shared types only.

**In, in `libs/rendering/renderer-2d/`:**

- A `Canvas2DRenderer implements SceneRenderer` that:
  - On `attach`, sizes the canvas for device-pixel-ratio and registers a `resize`/`devicepixelratio` listener.
  - On `render`, clears the canvas, applies the viewport transform, draws the tank rectangle (from `scene.tank.width × scene.tank.height` projected via `project2D`), and draws a faint mm grid (10 mm minor / 50 mm major).
  - On `hitTest`, returns `null` for now (no objects exist yet in Stage 0).
  - On `dispose`, removes listeners and clears the canvas.
- Coordinate handling: a single `viewportToCanvas` matrix is built per render; world-space mm → canvas pixels. **No custom 2D coord system** beyond the projection of 3D mm along −z.
- Idempotent: calling `render(scene, viewport)` twice produces identical pixels.

**Out:**

- Object drawing (hardscape / plants / substrate) — added incrementally per feature.
- Dirty-region redraw — implement when scene density justifies it (likely Stage 3+).
- `renderer-3d` — Stage 10.
- Selection handle rendering — F3.3.
- Overlays (golden ratio, thirds) — F5.3.

## Acceptance criteria

- [ ] `renderer-api` has tag `scope:rendering` and depends only on `domain/scene-model` + `domain/geometry`.
- [ ] `renderer-2d` has tag `scope:rendering` and depends only on `renderer-api` (+ transitive domain).
- [ ] Neither lib imports Angular, NgRx, RxJS, Electron, or any platform implementation.
- [ ] `render` is idempotent: two calls with the same args produce byte-identical canvas state (verified via canvas snapshot).
- [ ] No mutation of `scene` — verified by deep-equality check before/after render in a test.
- [ ] `dispose` removes every listener (verified by spying on `addEventListener` / `removeEventListener` or by counting).
- [ ] Mid-tier hardware target: 60fps with the empty tank + grid. Trivial at Stage 0 but profile it.

## Testing

- **Unit:** projection math, viewport-to-canvas matrix construction, device-pixel-ratio handling.
- **Integration:** snapshot test of a rendered tank-and-grid against a known scene at a known viewport, comparing the resulting `ImageData` to a checked-in PNG (tolerance 0 — the renderer is deterministic).
- **E2E:** covered indirectly by F0.6 boot test.

## Notes

- **`Scene`/`Viewport` lock-in.** Coordinate with `scene-model-engineer` on the exact `Scene` and `Viewport` shapes **before** you finalize the API. After F0.4 ships, changing these shapes is expensive — every consumer breaks.
- **No mid-stage interface drift.** Once `SceneRenderer` is shipped, additions are fine, _changes_ require a deliberate ADR. Stage 10 must drop in `renderer-3d` against the same interface.
- **Headless variant.** The export pipeline (F6.1) will reuse this renderer offscreen. Don't bake in assumptions that require a live DOM — accept a `RenderSurface` and let the caller provide it.
