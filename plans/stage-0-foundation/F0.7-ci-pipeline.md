# F0.7 — CI pipeline

**Stage:** 0 — Foundation & Walking Skeleton
**Owner:** `nx-workspace-engineer`
**Collaborators:** `test-engineer`
**Status:** Not started

## Goal

Wire CI so that every PR runs `nx affected` for lint/test/build, the OS matrix runs on `main`, and the merge-blocking quality gates from plan §3 are in place from day one.

## Spec reference

Plan §3 (tooling & quality gates), Stage 0 F0.7.

## Dependencies

**Requires:** F0.1 (workspace must exist).
**Enables:** every subsequent merge (CI guards quality).

## Scope

**In, in `.github/workflows/`** (or equivalent if the agent picks a different CI host — but document the choice):

- **PR workflow** (`pr.yml`):
  - Trigger: PR opened/synced against `main`.
  - Runs on Linux only for speed.
  - Steps: checkout → pnpm install (cached) → `nx affected -t lint test build` against the PR's base branch.
  - Posts a clean summary including affected projects and timings.
- **Main workflow** (`main.yml`):
  - Trigger: push to `main`.
  - Matrix: `ubuntu-latest`, `macos-latest`, `windows-latest`.
  - Steps: full `nx run-many -t lint test build e2e`.
  - Uploads test artifacts (Playwright traces on failure).
- **Merge-blocking gates** (required status checks on `main`):
  - `lint` (includes the `@nx/enforce-module-boundaries` check)
  - `test` (unit + component)
  - `build` (web + desktop)
  - `coverage` — `domain/*` libs must be ≥90% (per plan §3); the gate fails the PR if not.
  - **`document-round-trip`** — a contract test that does not exist yet (lives in `libs/testing/` or as a domain test once F1.3 lands). For Stage 0, scaffold the job as a `pending` check that always succeeds, and convert it to a real check when F1.3 lands. Document the TODO clearly.
- Caching: pnpm store + Nx cache, both restored across runs via the Nx Cloud or a self-hosted runner cache key.
- Concurrency control: cancel in-progress runs for the same PR on new push.

**Out:**

- Code signing / notarization workflows for Electron releases — F6.4.
- Coverage upload to Codecov / equivalent — optional; recommend wiring it in here if low-effort.
- Release/publish workflow — post-v1.

## Acceptance criteria

- [ ] Opening a PR against `main` triggers `nx affected -t lint test build` and the result is visible.
- [ ] A push to `main` triggers the OS matrix run.
- [ ] Affected-graph correctness: a PR that only changes `domain/geometry` does not rebuild `apps/desktop`.
- [ ] Coverage gate works: a PR that drops `domain/*` coverage below 90% fails the gate.
- [ ] Module-boundary regression PR (deliberate violation) fails the lint check with a useful error message.
- [ ] `document-round-trip` pending check is registered as required and currently succeeds.
- [ ] All CI runs complete in <10 minutes on the PR workflow with a warm cache.

## Testing

- **Manual:** open a no-op PR to verify the workflow shape.
- **Regression test PRs (temporary, closed without merging):**
  - One that introduces a boundary violation — must fail.
  - One that drops coverage in a domain lib — must fail the coverage gate.
  - One that changes only an Angular feature — must skip building unaffected domain libs.

## Notes

- **Choose a CI host explicitly.** GitHub Actions is the default for an open-source project, but the agent should document the choice and have a fallback story (CircleCI, GitLab CI) so the project isn't locked in.
- **Nx Cloud.** Recommended for cache + distributed task execution. If skipped, document why and provide a self-hosted cache strategy.
- **Don't gate Stage 0 on a passing Playwright matrix.** Electron e2e on Windows can be flaky during initial setup; mark it `continue-on-error: true` for the first iteration with a TODO to harden by end of Stage 1.
- **Document round-trip placeholder.** When F1.3 lands, replace the no-op `document-round-trip` job with the real property test. Don't ship Stage 1 without it.
