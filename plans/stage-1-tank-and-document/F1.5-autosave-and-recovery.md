# F1.5 — Autosave & crash recovery

**Stage:** 1 — Tank Setup & Document Lifecycle
**Owner:** `electron-platform-engineer` (storage backends), `angular-feature-engineer` (effects + UI)
**Collaborators:** `aqua-document-guardian`, `test-engineer`
**Status:** Not started

## Goal

Never lose user work to a crash, a browser refresh, or a power cut. A background autosave writes drafts; on next launch, the app offers to restore them.

## Spec reference

Plan Stage 1 F1.5.

## Dependencies

**Requires:** F0.5 (StorageService), F1.3 (serialization), F1.4 (file IO + dirty tracking), F1.6 (NgRx dirty state).
**Enables:** Confidence in long editing sessions — assumed by every later stage.

## Scope

- **Storage backends** in `platform-web` and `platform-electron`:
  - Web: IndexedDB (one record per draft, keyed by `docId` or "untitled-<sessionId>").
  - Electron: `userData/drafts/<docId>.aqua` files.
- **NgRx effect** in `state/`:
  - Triggers on a debounced stream of document mutations (e.g. 1.5 s after the last edit, plus a hard ceiling every 30 s).
  - Serializes the active doc via F1.3 and writes via `StorageService` (web) or a dedicated `DraftService` (Electron path; choose interface placement deliberately).
  - On successful autosave, surface a discreet "Saved · 3s ago" indicator.
- **Recovery on launch:**
  - If a draft exists for the previously open doc (or untitled session), prompt: "We recovered unsaved changes from <relative time>. Restore them?"
  - On accept, load the draft into the store and mark dirty (so the next "Save" persists it to the real file).
  - On decline, delete the draft.
  - If multiple drafts exist (multiple docs open), prompt for each.
- **Draft cleanup:** drafts older than 14 days are pruned at app boot.
- **Crash detection:** a `sessionGuard` written at boot and cleared at clean shutdown; if it's still present at next boot, that's a crash → trigger the recovery prompt.

**Out:**

- Multi-version history / Time Machine for documents — post-v1.
- Conflict resolution between drafts and on-disk file changes — assume single-writer.

## Acceptance criteria

- [ ] Autosave debounce works: 100 rapid edits write one draft, not 100.
- [ ] Hard ceiling fires: a continuous stream of edits triggers at least one autosave every 30 s.
- [ ] Crash simulation (force-kill app mid-edit) → next launch offers recovery → restored state deep-equals the pre-crash state at the last debounce point.
- [ ] "Saved · Ns ago" indicator updates correctly and is announced to screen readers as a live region.
- [ ] Draft pruning runs at boot and deletes drafts older than 14 days.
- [ ] No autosave runs while the doc is loading (avoid overwriting on partial state).

## Testing

- **Unit:** debounce timing; session-guard logic; draft pruning age threshold.
- **Component:** the indicator's live-region semantics.
- **E2E:**
  - Force-quit during an edit (Playwright can kill the Electron process; for web, programmatically clear in-memory state and reload) → recovery prompt → restore → state matches.
  - Decline recovery → draft deleted.
  - The autosave indicator updates within the expected window after edits.

## Notes

- **Don't autosave to the user's chosen file path.** Autosave writes to a _draft_ location; explicit Save (F1.4) writes to the user's file. This keeps "Save" intentional and avoids surprising the user with disk writes to their named files.
- **Crash detection is best-effort.** OOM kills, sudden power loss, BSODs may leave the session guard, which is fine — the recovery prompt covers them. The risk is false-positive prompts after legitimate clean shutdowns that failed to clear the guard; surface "Discard" prominently so users aren't trapped.
- **Don't run autosave on an invalid document.** If the in-memory doc fails F1.3 validation, skip the autosave and log; better to lose the last 1.5 s of edits than to write a corrupt draft.
