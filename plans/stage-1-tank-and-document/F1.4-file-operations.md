# F1.4 — File operations (New / Open / Save / Save As)

**Stage:** 1 — Tank Setup & Document Lifecycle
**Owner:** `electron-platform-engineer` (Electron half), `angular-feature-engineer` (web half + UI)
**Collaborators:** `aqua-document-guardian`, `test-engineer`
**Status:** Not started

## Goal

Implement real New / Open / Save / Save As on both platforms via the `platform-api` interfaces — File System Access API on web, native dialogs + IPC on Electron — replacing the F0.5 stubs.

## Spec reference

Plan Stage 1 F1.4; `platform-api` definitions from F0.5.

## Dependencies

**Requires:** F0.5 (the interface), F1.3 (serialization).
**Enables:** F1.5 (autosave reuses the IO paths), F1.6 (NgRx tracks dirty state), F6.1 (image export uses the same dialog idiom).

## Scope

**Web (`platform-web/`):**

- File System Access API (`window.showOpenFilePicker`, `window.showSaveFilePicker`).
- Persist file handles via IndexedDB so reopening a recent doc doesn't re-prompt.
- Graceful fallback for browsers without File System Access (Firefox): download/upload via `<a download>` and `<input type=file>`; warn the user that "Save" downloads a new copy each time.

**Electron (`platform-electron/` + main process):**

- IPC channels:
  - `file:open` — `dialog.showOpenDialog`, read file, return `{ id (path), bytes, name }`.
  - `file:save` — write to the path associated with `id`; return `{ id }`.
  - `file:saveAs` — `dialog.showSaveDialog`, write, return `{ id }`.
- Every handler validates its IPC payload before touching the filesystem.
- Path handling: never expose absolute paths to the renderer except as opaque `id` strings.

**Shared / UI (`features/editor-shell/`):**

- New / Open / Save / Save As menu entries (Electron native menu; web kebab menu).
- Keyboard shortcuts: Cmd/Ctrl+N, Cmd/Ctrl+O, Cmd/Ctrl+S, Cmd/Ctrl+Shift+S.
- "Save before closing" prompt when the doc is dirty — uses `DialogService.confirm`.
- "Recent files" list — backed by `StorageService`.

**Out:**

- Autosave / crash recovery — F1.5.
- Multi-window / multi-document support — post-v1.
- File watching / collaborative edits — out of scope entirely.

## Acceptance criteria

- [ ] New: creates an untitled empty document in the store; dirty flag false.
- [ ] Open: prompts, reads, validates via F1.3 schema, replaces the active doc; recent-files list updated.
- [ ] Save: writes back to the same file; dirty flag clears.
- [ ] Save As: prompts for a new path; subsequent Save writes there.
- [ ] Round-trip: open(save(scene)) deep-equals scene (covered by F1.3 property test, but smoke-test through the UI here).
- [ ] Invalid file (corrupt JSON, missing required fields) shows an explainable error, not a crash.
- [ ] Keyboard shortcuts work on both platforms; menu items are correct on Electron's native menu.
- [ ] Electron IPC handlers reject malformed payloads with a typed error rather than crashing.

## Testing

- **Unit:** payload validation in IPC handlers; recent-files store cap (e.g. 10 entries, dedupe, LRU eviction).
- **Component:** menu wires to actions; dirty prompt appears when expected.
- **E2E (web + electron):**
  - Create custom tank → save → reopen → identical (the Stage 1 milestone test).
  - Open a corrupt fixture → see the error toast, not a crash.
  - Save before closing with unsaved work → confirm dialog appears.

## Notes

- **File System Access browser support.** Chromium-based browsers support it; Firefox/Safari mostly don't (as of 2025–26). The fallback is acceptable but document it in the user-facing docs and surface it in-app on first save in unsupported browsers.
- **Don't leak fs paths to the renderer.** Use opaque `id` strings; the renderer never reasons about path structure.
- **Atomic writes on Electron.** Write to a `.aqua.tmp`, fsync, then rename — avoids corrupting a doc if the process dies mid-save.
