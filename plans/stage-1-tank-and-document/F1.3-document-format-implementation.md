# F1.3 — Document format implementation

**Stage:** 1 — Tank Setup & Document Lifecycle
**Owner:** `aqua-document-guardian`
**Collaborators:** `scene-model-engineer`, `test-engineer`
**Status:** Not started

## Goal

Realize the v1 `.aqua` format in code: move the canonical TypeScript types into `libs/domain/document/`, implement JSON-Schema validation on load, build the ZIP container reader/writer, and scaffold the Migration chain so v1→v1 is a no-op and the next version's slot is ready.

## Spec reference

Plan §2.7 (document format), Stage 1 F1.3; `aqua-document.ts`, `aqua-document.schema.json`, `example.aqua.json` at the repo root.

## Dependencies

**Requires:** F0.1, F0.3 (the in-memory `Scene` shape — must round-trip with `AquaDocument`).
**Enables:** F1.4 (file IO uses this), F1.5 (autosave uses this), every later feature that persists data.

## Scope

**In, in `libs/domain/document/`:**

- **Types:** move (or re-export) the contents of repo-root `aqua-document.ts` into this lib. The root file becomes a pointer / is deleted in favor of the lib being the source of truth. Document the migration in `CLAUDE.md`.
- **JSON Schema:** move `aqua-document.schema.json` into the lib (`libs/domain/document/schemas/aqua.v1.schema.json`).
- **Validation:** `validateDocument(json: unknown): Result<AquaDocument, ValidationError[]>` using `ajv` (Draft 2020-12) or `zod` (if the agent prefers; document the choice). Validation runs on every load.
- **Serialization:** `serializeDocument(doc: AquaDocument): Uint8Array` and `deserializeDocument(bytes: Uint8Array): Promise<Result<AquaDocument, ...>>`. The bytes are either bare JSON (UTF-8) or a ZIP — readers sniff for ZIP magic and accept both.
- **ZIP container:** read/write `document.json`, optional `assets/`, optional `thumbnail.png`. Use a small dependency (`fflate` or `jszip`) — pick one and stick with it.
- **`Migration` chain scaffold:**
  ```ts
  interface Migration<From, To> {
    from: number;
    to: number;
    apply(doc: From): To;
  }
  const migrations: Migration<any, any>[] = [
    // v1 → v1 is identity for now
  ];
  function migrate(doc: { schemaVersion: number; [k: string]: unknown }): AquaDocument { ... }
  ```
  `migrate` runs all applicable migrations up to the latest supported version, then validates the result.
- **Round-trip property test** — the merge-blocking contract test from plan §3 lands here:
  - Generate random valid documents (use fast-check + a strategy that produces well-typed `AquaDocument` instances).
  - Assert `deserialize(serialize(doc))` deep-equals `doc` for every generated doc.
- **In-memory ↔ on-disk mapping** — explicit, tested. If the in-memory `Scene` from F0.3 is literally `AquaDocument` minus the envelope (`format`, `schemaVersion`, `meta`), that mapping is trivial; otherwise document the mapping in code.

**Out:**

- The File System Access / Electron file IO that calls these functions — F1.4.
- Migrations to a future v2 — write when v2 is needed.
- Asset (image) handling beyond storing arbitrary bytes — F6.3 takes this further.

## Acceptance criteria

- [ ] The repo-root `aqua-document.ts` either lives in this lib or is a thin re-export pointer; there is one source of truth.
- [ ] `validateDocument(example)` accepts `example.aqua.json`.
- [ ] `validateDocument(broken)` rejects with an error that names the offending field path.
- [ ] Round-trip property test runs in CI and is wired as a merge-blocking gate (replacing the F0.7 placeholder).
- [ ] ZIP and bare-JSON variants both load successfully — verified by integration tests with a known fixture of each shape.
- [ ] `Migration` chain runs v1→v1 as identity and is exercised by a test.
- [ ] No Angular / DOM / Electron / NgRx imports.
- [ ] Lib has tag `scope:domain`.

## Testing

- **Unit:** validate accept/reject cases per field. Each `Migration` step (just identity for now). Schema-version handling (too old / too new / valid).
- **Property tests (merge-blocking):** the round-trip described above. CI gate.
- **Integration:** read a known ZIP fixture; read a known bare-JSON fixture; round-trip both back to bytes deterministically.
- **E2E:** none here; F1.4 covers the user-facing flow.

## Notes

- **Lock-step rule.** Any field change touches `aqua-document.ts`, the JSON Schema, AND a migration. The `aqua-document-guardian` sub-agent's prompt enforces this. Don't let a "one-line type change" slip in without the schema mirror update.
- **Forward compatibility.** Older readers must preserve unknown `extensions` and unknown per-object optional fields rather than dropping them. Validate this via a "future-doc fixture" — a document with extra fields beyond v1 — that loads, edits, and saves while preserving the extras.
- **Determinism of serialization.** Object key order in `JSON.stringify` is implementation-defined; if byte-identical round-trips matter (they likely don't, but consider), use a stable stringify. Otherwise document that "deep-equal after parse" is the contract, not "byte-identical bytes."
