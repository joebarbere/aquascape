# F1.6 — NgRx document store

**Stage:** 1 — Tank Setup & Document Lifecycle
**Owner:** `angular-feature-engineer`
**Collaborators:** `scene-model-engineer`, `test-engineer`
**Status:** Not started

## Goal

Establish the NgRx feature store that holds the open document plus ephemeral editor state. This is the integration point between Angular features and the framework-free `Scene`.

## Spec reference

Plan §2.6 (state management), Stage 1 F1.6.

## Dependencies

**Requires:** F0.3 (Scene + Commands), F1.3 (document serialization for save/load actions).
**Enables:** every feature dispatches into this store.

## Scope

**In, in `libs/state/document/`:**

- **State shape:**
  ```ts
  interface DocumentState {
    docId: string | null; // platform-api FileService id, or null for untitled
    fileName: string | null; // display only; the platform owns the real handle
    scene: Scene; // authoritative document content
    history: History; // undo/redo stack (from F0.3)
    dirty: boolean;
    isLoading: boolean;
    lastSavedAt: number | null; // epoch ms
    lastAutosavedAt: number | null;
    error: { code: string; message: string } | null;
    recentFiles: { id: string; name: string; openedAt: number }[];
  }
  ```
- **Actions:** `documentNew`, `documentOpenRequested` / `…Succeeded` / `…Failed`, `documentSaveRequested` / `…Succeeded` / `…Failed`, `documentSaveAsRequested` / `…Succeeded`, `commandApplied` (carries the Command + the new scene), `undoRequested`, `redoRequested`, `autosaveSucceeded`, `recoveryPromptResolved`.
- **Reducer:** updates `scene` via Commands' `apply`; manages `dirty`, `history`, `lastSavedAt`. The reducer **never reaches into the Scene directly** — it always goes through a Command (the action carries one).
- **Effects:**
  - `openDocument$` — calls `FileService.openDocument`, validates via F1.3, dispatches success/fail.
  - `saveDocument$` — serializes via F1.3, calls `FileService.saveDocument`.
  - `saveAsDocument$` — same but routes to `saveDocumentAs`.
  - `autosave$` — debounced stream of `commandApplied`, triggers F1.5 autosave.
- **Selectors:** `selectScene`, `selectActiveLayer`, `selectDirty`, `selectCanUndo`, `selectCanRedo`, `selectRecentFiles`, `selectError`. Selectors wrap pure selectors from `domain/scene-model` rather than reimplementing them.

**Out:**

- UI components dispatching specific feature actions — each feature lib owns its own UI.
- A separate "editor" store for selection / tool / viewport — recommend co-locating in this store for now and splitting later if it grows. (Or split into `state/editor/` from the start — agent's discretion; document the choice.)

## Acceptance criteria

- [ ] Lib has tag `scope:state`.
- [ ] Dispatching `commandApplied` updates `scene` via the carried Command and increments dirty.
- [ ] `undoRequested` pops the history stack and restores the previous scene.
- [ ] Save → success transitions clear dirty and set `lastSavedAt`.
- [ ] Selectors are memoized (verified by counting selector function invocations in a test).
- [ ] All effects are testable with `provideMockActions` and don't require a running platform.

## Testing

- **Unit:** reducer for each action; selectors with snapshot inputs.
- **Marble tests (jasmine-marbles or RxJS testing):** effects given mocked services.
- **Integration:** dispatch a sequence — new → command → save → assert dirty cleared.

## Notes

- **Don't store the platform `id` in `Scene`.** The doc itself is portable and platform-agnostic; the `id` is platform metadata that lives in NgRx state only.
- **`commandApplied` carries the Command, not just the new scene.** Carrying the Command lets the autosave / collab story replay or log mutations later.
- **`history` in NgRx vs. in `Scene`.** History is editor state, not document state — it lives in NgRx, not in the `.aqua` file. The reducer manages it as a sibling to `scene`.
