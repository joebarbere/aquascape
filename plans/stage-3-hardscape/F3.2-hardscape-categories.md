# F3.2 — Hardscape categories

**Stage:** 3 — Hardscape Tool
**Owner:** `angular-feature-engineer`
**Collaborators:** `catalog-engineer`, `test-engineer`
**Status:** Not started

## Goal

Group the hardscape palette into recognizable categories (rock types: Seiryu, Ryuoh, Dragon Stone, Frodo Stone, lava; driftwood: spiderwood, manzanita, malaysian, mopani) with filtering and search.

## Spec reference

Plan Stage 3 F3.2.

## Dependencies

**Requires:** F3.5 (catalog entries exist with category tags), F3.1 (palette UI).
**Enables:** scalable palette as catalog grows.

## Scope

**In:**

- Each `HardscapeCatalogEntry` carries a `category` (rock subtype string or driftwood subtype string) plus a top-level `kind` (`rock` | `driftwood`).
- Palette UI:
  - Top-level kind tabs (Rocks / Driftwood).
  - Category filter chips (multi-select, persisted via UI prefs).
  - Text search across name + tags.
  - Virtualized list for catalog > 100 entries.

**Out:**

- Per-category curated images / hero cards — nice-to-have polish.
- Tag taxonomies beyond `category` — pile on later if a need shows up.

## Acceptance criteria

- [ ] Filter chips narrow the palette correctly.
- [ ] Search matches name and tags case-insensitively.
- [ ] Filter + search combine with AND semantics.
- [ ] Virtualized list is performant with 500+ entries.
- [ ] Filter and search inputs are keyboard accessible and announce result counts to screen readers.

## Testing

- **Unit:** filter logic; search-string tokenization.
- **Component:** filter chips, search input, result count rendering.

## Notes

- **Category list is data-driven.** Don't hardcode "Seiryu / Ryuoh / …" in the UI; derive from the loaded catalog's distinct `category` values.
- **Don't over-design.** Two-axis filter (kind + category) plus search is enough. Resist faceted-search rabbit holes for v1.
