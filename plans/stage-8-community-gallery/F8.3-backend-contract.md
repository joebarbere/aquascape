# F8.3 — Backend contract (interface)

**Stage:** 8 — Community Gallery
**Owner:** `angular-feature-engineer` (interface), `electron-platform-engineer` (token storage)
**Collaborators:** `test-engineer`
**Status:** Not started

## Goal

Define the gallery backend as an interface so this project can self-host or run gallery-less. The reference implementation can be a small hosted service; downstream forks plug in their own.

## Spec reference

Plan Stage 8 F8.3.

## Dependencies

**Requires:** F1.3 (document format), F0.5 (platform abstraction patterns).
**Enables:** F8.1, F8.2.

## Scope

**In, in `platform-api/`:**

- `GalleryService` interface:
  ```ts
  interface GalleryService {
    isAvailable(): Promise<boolean>;
    list(query: GalleryQuery): Promise<GalleryPage>;
    get(id: GalleryId): Promise<GalleryDetail>;
    publish(args: {
      aquaBytes: Uint8Array;
      thumbnail: Uint8Array;
      meta: PublishMeta;
    }): Promise<{ id: GalleryId; url: string }>;
    delete(id: GalleryId): Promise<void>;
  }
  ```
- Auth token handling: tokens live in OS secure storage (Electron) or sessionStorage (web). Never in the document.
- Reference HTTP implementation for a TBD backend (could be a minimal Express / Hono service; could be a static-files-based gallery if community goes that direction). Choose one and document.
- A `MockGalleryService` for tests and offline development.

**Out:**

- The actual server implementation — separate project / repo.
- Federation / multi-source galleries — out of scope.

## Acceptance criteria

- [ ] Interface is fully specified.
- [ ] `MockGalleryService` is usable in tests and dev.
- [ ] Tokens never appear in serialized documents (sanitization test).
- [ ] `isAvailable()` returns false cleanly when no backend is configured.

## Testing

- **Unit:** Mock service behaviors; token sanitization.
- **Integration:** reference HTTP client against a fake server.

## Notes

- **Don't lock in to a single backend.** The contract must allow self-hosted, S3+JSON-index, or fully serverless implementations. Keep it transport-shaped, not implementation-shaped.
- **Coordinate with the eventual server project.** This contract is the source of truth for the wire format.
