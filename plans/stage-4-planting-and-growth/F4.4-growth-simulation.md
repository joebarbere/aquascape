# F4.4 — Growth simulation (deterministic, time-sliced)

**Stage:** 4 — Layers & Planting Tool
**Owner:** `growth-sim-engineer`
**Collaborators:** `catalog-engineer`, `scene-model-engineer`, `renderer-engineer`, `angular-feature-engineer`, `test-engineer`
**Status:** Not started

## Goal

A pure, seeded, deterministic simulation that takes a `PlantObject` and a number of weeks, and returns the rendered size/spread at that point in time. A time slider in the UI lets the user preview the scape at any week from 0 to maturity. This is the signature differentiator.

## Spec reference

Plan Stage 4 F4.4; growth params in plant catalog (F4.1).

## Dependencies

**Requires:** F4.1 (plants with growth params), F4.2, F1.3 (doc seed already in the schema), `domain/growth-sim` lib scaffolded.
**Enables:** richer Stage 4 milestone; supports the time-aware preview that the rest of the app references.

## Scope

**In, in `libs/domain/growth-sim/`:**

- Pure function:
  ```ts
  function growth(
    plant: PlantCatalogEntry,
    plantInstance: { seed: number; plantedAtWeek: number },
    currentWeek: number,
  ): RenderedShape;
  ```
  where `RenderedShape` is `{ heightMm: number; spreadMm: number; jitter: { angle: number; offset: Vec2 } }`.
- Engine version string baked into outputs (`engine: { version: '1.0.0' }`) so old documents replay with their original engine.
- Seeded PRNG (recommend mulberry32 or sfc32) — document the choice. Sub-seed derivation: `subSeed = hash(parentSeed, namespace, index)`.
- `growthCurve` interpolation per catalog field: linear / sigmoid / sqrt.
- Saturation at `maturityWeeks` — `growth(plant, instance, week >= maturityWeeks) === growth(plant, instance, maturityWeeks)`.

**In, in `renderer-2d`:**

- When rendering a `PlantObject`, call `growth(...)` with the document's `currentWeek` (kept in editor state) and use the resulting size/spread/jitter to draw the plant.

**In, in `features/planting-tool/`:**

- Time slider component: 0..max(plant.maturityWeeks across the scene) weeks. Default to "mature" (week = max).
- Web Worker boundary: large scenes (>200 plants) move growth evaluation to a worker. Worker contract is the same pure function; results are sent back as a `Map<ObjectId, RenderedShape>`.

**Out:**

- Persisting computed growth into the scene — DON'T. Recompute on render; the input space (plant + seed + week) is small enough.
- Plant nutrient / parameter simulation (CO2 effects, light effects) — out for v1.

## Acceptance criteria

- [ ] `growth(p, i, week)` is pure: same inputs → byte-identical output.
- [ ] Saturation: `growth(p, i, w >= maturityWeeks) === growth(p, i, maturityWeeks)`.
- [ ] `engine.version` is present in outputs and never silently shifts behavior on bump.
- [ ] Time slider re-renders the canvas in <50 ms for scenes with <500 plants (no worker), <100 ms with the worker for >500.
- [ ] Reproducibility property test: 1000 iterations of `growth` with random plants + seeds + weeks produce stable hashes across runs and platforms.
- [ ] Time slider doesn't mark the document dirty — it's view state, not document state.

## Testing

- **Unit:** curve math at `t=0`, mid, maturity; saturation; seed reproducibility.
- **Property:** stable-hash reproducibility (the big one).
- **Snapshot:** rendered plant at fixed (plant, seed, weeks) tuples matches a checked-in snapshot.
- **Component:** time slider drives renderer; doesn't dirty doc.

## Notes

- **PRNG choice is sticky.** Once shipped, changing the PRNG changes every existing document's growth output. Pin the choice with an ADR and a test that asserts a known (plant, seed, week) tuple produces a known output forever.
- **Worker boundary.** Pure functions transport cleanly; structured-clone the inputs. Don't try to share refs with the main thread.
- **`currentWeek` is per-document editor state.** It's persisted in NgRx and optionally surfaced via the URL (`?week=12`) but not stored in the document itself.
